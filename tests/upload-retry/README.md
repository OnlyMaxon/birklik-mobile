# Прогон правил повтора загрузки

```
node tests/upload-retry/run.mjs
```

Проверяется `src/lib/upload-retry.ts` — повтор отправки снимка и срок на
зависание. Двадцать три проверки, около двух секунд, ставить ничего не нужно.

## Зачем это вообще есть

Тестов в приложении нет, и завести их нельзя: это значит поставить пакеты, а
`pnpm` здесь запрещён. При этом правила повтора — самый тонкий код подачи: он
гоняет таймеры, прерывает чужие обещания и считает время, которое идёт не всегда.
Проверить его глазами не вышло. Первый же прогон нашёл настоящую ошибку: при
зависании наверх уходил код `storage/canceled` вместо `storage/stalled`, потому
что прерывание отклоняет обещание быстрее, чем выбрасывается своя ошибка. То
есть донесение сказало бы «отменено» там, где загрузка повисла, — ровно та
подмена смысла, из-за которой прошлый отказ искали пять месяцев.

Вторую нашёл перечитыванием, уже без прогона: `start()` стоял ВНЕ `try`, и отказ, брошенный
сразу — не обещанием, а броском, — пролетал мимо повтора целиком. Ни четырёх попыток, ни записи
в донесение. Такая дыра страшнее обычной ошибки: открывается только на одном виде отказа и
именно в этот раз ведёт себя не так, как написано в её же документации. Закрыто и покрыто
сценариями 8 и 9.

## Что именно проверяется

| сценарий | о чём |
| --- | --- |
| удача с первого раза | повтор не вмешивается, когда всё хорошо |
| отказ, затем удача | `storage/unknown` от 23.11 лечится повтором |
| молчащая загрузка | срок прерывает и начинает заново |
| отказ всегда | ровно четыре попытки, наверх настоящий код Firebase |
| висит всё | наверх уходит `storage/stalled`, экран не остаётся навсегда |
| свёрнуто | срок НЕ идёт: здоровую фоновую загрузку не прерываем |
| свёрнуто | новая попытка не начинается до возврата |
| отказ броском | `putFile` может отказать СРАЗУ, не обещанием — повтор обязан сработать и тут |
| бросок всегда | отказ уходит наверх с настоящим кодом, без зацикливания |
| подписки | слушатели `AppState` не текут |

⚠️ Подделка `react-native` (`stub-react-native.js`) отдаёт только `AppState` и
позволяет переключать «на виду / в фоне» руками. Firebase не участвует вовсе:
отправка подменяется и ведёт себя по заданному списку.

## Почему папка исключена из проверки типов

`tests/**` стоит в `exclude` у `tsconfig.json`, и это не лень. `check.ts`
написан против ПОДДЕЛКИ `react-native` и просит у неё `__setState`, которого у
настоящего пакета нет, — проверка типов приложения на этом справедливо падает.
Код сценариев проверяется не типами, а тем, что он исполняется: прогон
печатает каждую проверку и возвращает ненулевой код при любом провале.

⚠️ Поэтому `node tests/upload-retry/run.mjs` надо звать ОТДЕЛЬНО: `pnpm
typecheck` этих файлов больше не видит и о поломке в них не скажет.
