# Что лежит в `android/` и не лежит в гите

Папка `android/` закрыта `.gitignore` (строка `/android`), и это намеренно: `expo prebuild` в
этом проекте запускать нельзя — он стирает её вместе с подписью и вычищенным манифестом. Цена
такого решения в том, что **правки внутри `android/` существуют только на машине владельца**.

Здесь лежит то, чем их можно восстановить, если папка потеряется или проект будут клонировать
заново. Это не сборочные файлы, а исходники правок, сделанных руками.

## 1. Звуки уведомлений

```
sounds/booking.wav      → android/app/src/main/res/raw/booking.wav
sounds/moderation.wav   → android/app/src/main/res/raw/moderation.wav
```

Скопировать как есть. Имена значимы: по ним канал ищет звук
(`android.resource://az.birklik.app/raw/booking`), а в `res/raw` допустимы только строчные буквы,
цифры и подчёркивание.

Звуки не нарисованы руками, а **посчитаны**: `sounds/make-sounds.py` воспроизводит их точно,
байт в байт. Запуск — `python make-sounds.py` в этой папке, сторонних пакетов не нужно.

⛔ **Менять звук нельзя просто так.** Настройки канала Android запоминает при первом создании и
больше не перезаписывает: у всех, кто уже поставил приложение, останется прежний. Другой звук
означает НОВЫЙ идентификатор канала (`booking_v2`) и на сервере тоже. Этот выбран владельцем
2026-11-22.

## 2. Каналы уведомлений

Создаются в `android/app/src/main/java/az/birklik/app/MainApplication.kt`, в методе
`createNotificationChannels()`, который вызывается из `onCreate()`. Подробный разбор — в
`Architecture.md`, раздел «Звук уведомления живёт в КАНАЛЕ». Если файл придётся собирать заново,
важны ровно четыре вещи:

```
id          booking          moderation
важность    IMPORTANCE_HIGH  IMPORTANCE_HIGH      ниже — молча падает в шторку
звук        raw/booking      raw/moderation       + AudioAttributes USAGE_NOTIFICATION
вибрация    [0,220,140,220]  [0,260]              два толчка против одного
```

⚠️ Идентификаторы обязаны совпадать с `channelId`, который подставляет сервер в
`firebase-functions/src/notifications/send-push.ts` репозитория сайта. Разойдутся — FCM нарисует
уведомление в своём резервном канале, со системным звуком и без всплытия, **и ошибки не будет**.

⚠️ Названия каналов — в `res/values/strings.xml` (`channel_booking_name` и остальные три). Их
человек видит в системных настройках телефона, а те читают язык ТЕЛЕФОНА, не выбранный в
приложении, — поэтому они только по-азербайджански.

## 3. Манифест: вертикальная ориентация не требование к железу

`android/app/src/main/AndroidManifest.xml`:

```xml
<uses-feature android:name="android.hardware.screen.portrait" android:required="false"/>
```

У `MainActivity` стоит `android:screenOrientation="portrait"`, и Android из этого САМ выводит
обязательную аппаратную возможность `android.hardware.screen.portrait`. Консоль Play тогда
пишет «приложение доступно не на всех устройствах»: установить его не могут те, кто портрет не
умеет — часть планшетов, Desktop/ChromeOS и Android XR. Строка снимает требование, не меняя
ориентацию. Замечено владельцем 2026-11-22; в выложенной 1.0.16 (code 20) её ещё НЕТ.

## 4. Номер версии

`android/app/build.gradle`, `versionCode` и `versionName`. ⚠️ Правятся **руками и в двух
местах**: здесь ради сборки и в `app.json` ради донесений об ошибках — они берут версию оттуда,
потому что нативное значение читать нечем. Разойдутся — донесение соврёт о том, какая сборка
сломалась.
