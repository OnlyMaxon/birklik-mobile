# Анкета Data safety в Google Play Console

Где: Play Console → приложение → **Политика → Контент приложения** (Policy → App content).
Там же отдельным пунктом лежит **Рекламный идентификатор** (Advertising ID).

Составлено 2026-09-25 по коду `versionCode 3`. Каждый ответ ниже подтверждён либо файлом
сборки, либо местом в исходниках — там, где это не так, прямо написано «решение за тобой».

⚠️ Отвечать наугад нельзя: Google сверяет анкету с поведением приложения и отклоняет за
расхождение. Если что-то из списка изменится — анкету надо править вместе с кодом.

---

## Рекламный идентификатор — ответ «НЕТ»

Подтверждено артефактом, а не предположением: разрешения
`com.google.android.gms.permission.AD_ID` **нет ни в одном** слитом манифесте релизной
сборки. Из Firebase подключены `app`, `app-check`, `auth`, `firestore`, `messaging`,
`storage` — **аналитики нет**, а именно она обычно и приносит рекламный идентификатор.

Проверить при следующей сборке:

```bash
grep -c AD_ID android/app/build/intermediates/packaged_manifests/release/*/AndroidManifest.xml
```

## Передача третьим лицам

Google считает «передачей» уход данных **к третьей стороне**, а не к обработчику, который
работает по твоему поручению.

| Куда | Что уходит | Это передача? |
|---|---|---|
| Firebase (Google) | всё хранилище и вход | **Нет** — обработчик по поручению |
| `nominatim.openstreetmap.org` | текст адреса объявления | Нет — это описание объекта, не данные пользователя |
| CARTO | координаты плиток карты | Нет — личных данных не содержат |
| ~~`ui-avatars.com`~~ | ~~имя пользователя в адресе картинки~~ | ✅ **Убрано 2026-09-25** |

## Удаление данных

В анкете есть шаг про удаление. Ответы:

- удаление аккаунта **из приложения** — есть (кнопка в настройках);
- **веб-адрес** для тех, у кого приложения уже нет — `https://birklik.az/account-deletion`;
- что удаляется: объявления с фотографиями, брони, комментарии, оценки, уведомления, профиль
  и сама запись входа;
- что **не** удаляется: записи о платежах — они обезличиваются (`userId` → `deleted`), потому
  что это журнал выручки, по которому сходятся суммы с банком и Google Play.

Проверено живьём 2026-09-25 на непустом аккаунте: счётчики функции сошлись с независимым
обходом базы до единицы.

## ✅ Лишние разрешения убраны 2026-09-25

Было: `RECORD_AUDIO` (микрофон) и `SYSTEM_ALERT_WINDOW` (поверх других окон) из шаблона Expo,
`ACCESS_FINE_LOCATION` и `ACCESS_COARSE_LOCATION` от `@maplibre/maplibre-react-native`. Ничем
из них приложение не пользовалось, но пользователь видел их в карточке.

Убрано правкой `android/app/src/main/AndroidManifest.xml` (два удалены, двум проставлен
`tools:node="remove"`) плюс `blockedPermissions` в `app.json` — чтобы пережило `expo prebuild`.

⚠️ `expo prebuild` НЕ запускался: он стирает `android/` вместе с `versionCode` и настройкой
подписи. Папка правится руками.

Осталось в сборке `versionCode 3` — всё используется:

```
INTERNET  ACCESS_NETWORK_STATE  ACCESS_WIFI_STATE
CAMERA  READ_EXTERNAL_STORAGE  WRITE_EXTERNAL_STORAGE   (снимки объявления)
POST_NOTIFICATIONS  VIBRATE  WAKE_LOCK                  (пуши)
com.android.vending.BILLING                             (покупка тарифа)
READ_GSERVICES
```

Проверять после каждой сборки:

```bash
grep -o 'android:name="[a-z.]*permission[^"]*"'   android/app/build/intermediates/packaged_manifests/release/*/AndroidManifest.xml | sort -u
```

## ⚠️ Отпечаток ключа при проверке APK на телефоне

Локально собранный APK подписан **ключом загрузки** `fa7f0c0e…`, а Play раздаёт приложение,
переподписав ключом `9a08fd35…`. В Firebase зарегистрированы только `9a08fd35…` и лишний
`d76238e9…` — **ключа загрузки там нет**.

Значит локальный APK **не пройдёт App Check**: объявления не загрузятся, экран будет пустым.
Это ровно то, что в сентябре три дня принимали за блокировку Google.

Выходы: либо добавить `fa7f0c0e…` в Firebase Console (настройки проекта → приложение Android →
отпечатки сертификата SHA), либо проверять через внутренний тест в Play, где подпись уже своя.
